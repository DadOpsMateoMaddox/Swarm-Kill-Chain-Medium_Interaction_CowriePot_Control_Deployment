P0-RCA-01 — SSH HOST-KEY SLOT CORRUPTION
=========================================
Cowrie 2.5.0 parses three independent host-key slots (source truth,
/opt/cowrie/src/cowrie/ssh/keys.py):
    line 19-20  rsa_public_key      / rsa_private_key
    line 67-68  ecdsa_public_key    / ecdsa_private_key
    line 89-90  ed25519_public_key  / ed25519_private_key

PRE-REPAIR STATE: only the rsa_* slot was configured, and the material in
it was Ed25519 on BOTH halves (matching fingerprints). No ed25519_* config
lines existed. No RSA key existed anywhere on the host.

CAUSAL CHAIN:
    client negotiates ssh-rsa host-key algorithm
      -> Cowrie retrieves key from rsa_* slot
      -> actual object is Ed25519
      -> Twisted asks Ed25519 key to sign as ssh-rsa
      -> BadSignatureAlgorithmError
      -> transport dies during KEX, before shell creation

Outcome depended entirely on which host-key algorithm the client chose,
which is why some sessions survived and others died.
